# TopTalents.Sprint — лендинг (Tilda) + аналитика формы

Исходники страницы `aiesecinkz.tilda.ws/toptalentssprint` и сборка в 5 кусков для вставки в Tilda.
Аналитика отвала по форме уходит в трекер (`utm-tracker`, раздел **Forms**).

```
src/
  css/main.css            стили (#tt), часть 1
  html/page.html          разметка блока T123, часть 2
  js/                     скрипт страницы, часть 3 (модули в общем замыкании, порядок — в build.mjs)
    config.js             ВСЁ, что меняется от набора к набору: id формы, проект, дедлайн, URL, поля
    i18n.js               RU/ENG
    analytics.js          аналитика формы (анонимная)
    countdown.js          обратный отсчёт и закрытие приёма
    ui-effects.js         анимации, лента этапов, FAQ, меню, модалка, курсор
    form.js               форма: обязательные поля, условные поля, отправка в Apps Script
    main.js               запуск
  i18n/en.json            английские строки для [data-i] (как массив E в исходной версии)
  i18n/ui.json            строки интерфейса RU/EN (meta, countdown, сообщения формы, модалка)
  assets/images/*.b64     картинки (тот же base64, не перекодированы); manifest.json — какая картинка в какой части
  assets/fonts/*.b64      шрифт HN
scripts/build.mjs         сборка src → dist/part1..5.html (+ all.html), печатает размеры
original/                 исходный код страницы (для сравнения поведения)
tests/same-behaviour.mjs  DOM новой и старой страницы совпадает в 11 сценариях × 3 режима
tests/simulate.mjs        27 визитов → коллектор → дашборд, сверка цифр
```

`npm run build` — собрать `dist/`. Зависимостей нет (Node 18+).

## Вставка в Tilda

1. Сайт → Настройки сайта → Ещё → HTML-код для вставки внутрь HEAD → заменить старое содержимое на **part4.html** (шрифт). *Не менялся — можно не трогать.*
2. Сайт → Настройки сайта → HTML-код перед `</body>` → **part5.html**. *Не менялся.*
3. Страница → Настройки страницы → Дополнительно → HTML-код внутрь HEAD → **part1.html**. *Не менялся.*
4. Блок T123 на странице → **part2.html**. *Не менялся.*
5. Страница → Настройки страницы → HTML-код перед `</body>` → **part3.html**. **Меняется только эта часть.**
6. Опубликовать страницу. Проверка: открыть `…/toptalentssprint?tt_debug=1`, в консоли браузера идут строки `[tt] page_view …`; в трекере **Forms** появится форма `tts-f26-registration` (сессии с `?tt_debug=1` помечены как тест и по умолчанию скрыты — включить «include test»).

## Что сделано

- Код разложен по модулям, конфиг в одном месте (`config.js`): дедлайн, `forceClosed`, id формы, slug проекта, URL коллектора и Apps Script, список полей с правилами «обязательное / по условию». Список обязательных полей, порядок для сообщения об ошибке, счётчик «Обязательные пункты» и аналитика строятся из этого списка — для следующего набора меняется только `config.js` (и тексты).
- Поведение проверено автоматически: `tests/same-behaviour.mjs` открывает старую и новую страницу и сравнивает DOM `#tt` после загрузки, смены языка, пустой отправки, «студент», «не готов к переезду», успешной отправки, FAQ, после дедлайна — на 1280 px, без reduced-motion и на 375 px. Совпадает всё, кроме намеренно исправленной подписи (баг 1 ниже).
- Аналитика: `visitor_id` (localStorage), `session_id` (sessionStorage, новая после 30 минут простоя), очередь событий, пачки каждые 3 с или по 10 событий, при уходе — `navigator.sendBeacon` (text/plain, без CORS preflight), запасной `fetch keepalive`. Всё под try/catch, форму не блокирует. Боты (navigator.webdriver, UA) не отправляются.
- События: page_view, section_view, cta_click (hero / header / menu / dock / final), lang_switch, faq_open, form_view, form_start, field_focus / field_blur (заполнено, валидно, длительность, длина — без значения), field_change (только select/галочки — значение-категория), field_shown / field_hidden (условные поля), field_error, submit_attempt, submit_blocked (какие обязательные пусты), submit_success, submit_error, modal_open, tg_join_click, abandon (последнее поле, заполненные поля, время), form_closed_view.
- `?tt_debug=1`: события в консоль, сессия помечается тестовой, форма после дедлайна открывается **только у этого посетителя**. Дедлайн и `forceClosed` для всех остальных не меняются.
- В заявку для Apps Script добавлены `session_id`, `visitor_id`, `is_test` — строку таблицы можно связать с воронкой и UTM в трекере.

## Найденные баги

Исправлены (поведение изменилось только здесь):
1. **Подпись поля «Направление обучения» ломалась при смене языка.** После RU→ENG→RU она становилась «Ваша специальность» (текст из разметки), а у студентов терялась пометка обязательности `*`. Теперь подпись пересчитывается при каждой смене языка.
2. **Порядок в сообщении «Начни с поля …» для студентов.** «Год обучения» добавлялся в конец списка обязательных, после согласий; сообщение и автофокус указывали не на первое по порядку пустое поле. Теперь порядок = порядок полей на странице.
3. **`FORCE_CLOSED = true` не закрывал форму визуально.** Закрытие срабатывало только из обратного отсчёта, когда дедлайн уже прошёл; досрочное закрытие лишь молча игнорировало отправку. Теперь `forceClosed: true` сразу показывает блок «приём закрыт». Сейчас там `false` — видимых изменений нет.

Убрано (мёртвый код): ссылка на несуществующий `#ttUniHint`; дубли комментариев COUNTDOWN и «ГОРИЗОНТАЛЬНАЯ ЛЕНТА»; поддержка казахского (`kk`), для которого не было ни одной строки.

Не трогал, нужно ваше решение:
4. В разметке счётчик изначально «0 / 10», а обязательных пунктов 11 (JS сразу исправляет на «0 / 11»). Чинится только правкой части 2.
5. Дата дедлайна живёт и в текстах: «Дедлайн: 10 сентября 2026, 23:59», «до 10 сентября», футер, текст «приём закрыт», meta description. Для следующего набора их нужно поменять вместе с `config.js` (это контент, не код).
6. Ссылки «Другие программы», «Подробнее» и «Связаться с менеджером» ведут на `aieseckz.vercel.app/r/tt_ogx` — **старый** деплой трекера. Если его отключить, ссылки сломаются. Нужно перевести их на новый домен трекера.
7. У FAQ нет `tt-faq-3` (нумерация 1, 2, 4, 5, 6) — косметика.

## Безопасность Apps Script

`TTS_SECRET` (`appsScriptSecret`) лежит в коде страницы, его видит любой посетитель: это **не защита**. Реальная защита должна быть на стороне Apps Script:
- проверка полей (email, телефон, длины);
- ограничение частоты через `CacheService` (например, не больше N заявок в минуту);
- дедупликация по email или телефону;
- при желании honeypot-поле.

### Минимальная правка Apps Script

Добавьте в таблицу 3 колонки в конец заголовка: `session_id`, `visitor_id`, `is_test`. В `doPost`, там, где собирается строка:

```js
function doPost(e) {
  var data = JSON.parse(e.postData.contents);
  // … существующая проверка secret и полей …
  sheet.appendRow([
    // … существующие колонки в том же порядке …
    data.session_id || '',   // связь с воронкой в трекере (Forms → сессия)
    data.visitor_id || '',
    data.is_test ? 'TRUE' : ''   // заявки с ?tt_debug=1 — тестовые, их можно отфильтровать
  ]);
  return ContentService.createTextOutput(JSON.stringify({ ok: true }))
    .setMimeType(ContentService.MimeType.JSON);
}
```

После правки: Deploy → Manage deployments → New version (URL не меняется).

## Трекер: деплой и миграция

Код в `utm-tracker`:
- `prisma/migrations/0008_form_analytics`: таблицы `AnalyticsForm`, `AnalyticsSession`, `AnalyticsEvent`. Существующие модели не менялись. БД — Postgres (Neon), миграция применяется при деплое (`scripts/migrate-production.mjs`).
- `POST /api/collect`: публичный коллектор.
  - Проверки: CORS-allowlist (`aiesecinkz.tilda.ws` и домен трекера), тело ≤ 64 КБ, ≤ 50 событий в пачке, ≤ 120 пачек в минуту с IP, схема zod.
  - Идемпотентность: id события = `<session>.<n>`, повторная пачка не создаёт дублей.
  - Сырой IP не хранится: только sha256 с дневной солью и страна из `x-vercel-ip-country`.
- Раздел **Forms**: воронка, таблица по вопросам, «где уходят», «Blocked on Send», срезы (источник, кампания, устройство, язык, город, релокация), последние сессии с хронологией, CSV (вопросы и сессии), фильтры (даты, источник, кампания, устройство, язык, город, «include test»). С папки проекта есть ссылка «Form drop-off →».
- Очистка: Vercel Cron (`vercel.json`, ежедневно) → `/api/cron/purge-analytics` удаляет сессии старше `ANALYTICS_RETENTION_DAYS` (по умолчанию 180 дней) вместе с событиями. Вручную: `npm run analytics:purge -- 90`.

Переменные окружения (Vercel → Settings → Environment Variables):

| Переменная | Нужна | Зачем |
|---|---|---|
| `CRON_SECRET` | да, для очистки | любая длинная случайная строка; Vercel Cron передаёт её сам |
| `ANALYTICS_RETENTION_DAYS` | нет | срок хранения, по умолчанию 180 |
| `ANALYTICS_ORIGINS` | нет | ещё сайты, с которых принимать события, через запятую (например, `https://aieseckz.tilda.ws`) |
| `IP_HASH_SALT` | уже есть | соль для хеша IP |

Связь с кампаниями: сессия хранит `utm_source / utm_campaign / …` и `click_id` из ссылки трекера, `projectSlug` = ключ папки проекта (`toptalentssprint-f26`). Поэтому данные формы ложатся рядом с кампаниями проекта и его EwA2oGX / EwA2MXP.

> Для улучшения формы мы собираем обезличенную статистику её заполнения: какие поля были заполнены (без самих ответов), сколько времени это заняло, на каком шаге форму закрыли, источник перехода (UTM-метки), тип устройства, язык страницы и страну.
