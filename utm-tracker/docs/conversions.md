# Конверсия (EwA2ELD)

Блок на странице проекта (`/projects/{slug}`), который по нескольким числам считает
коэффициенты. Сейчас включён тип **EwA2oGX**; **EwA2MXP** заготовлен в реестре, но выключен.
Названия (EwA2ELD, EwA2oGX, EwA2MXP, oGX, MXP, рега, шоуап, AIESEC.org signup) не
расшифровываются и не переводятся.

## Числа и формулы

| Код | В интерфейсе | Откуда |
|---|---|---|
| `projectRegs` | Реги на проект | Таблица регистраций проекта (Google Sheets или загруженный файл) без дублей и фейков. Запасной вариант — `registrants` из опубликованного отчёта Registration. |
| `regOgx` | Рега oGX | Уникальные заявки oGX-кампании проекта из нашей БД (таблица `Lead`): по ссылкам кампании или с её `utm_campaign`. Без дублей и фейков. |
| `showUp` | Шоуап | Вводит админ. |
| `aiesecOrgSignup` | AIESEC.org signup | Вводит админ (растёт со временем — фиксируйте снимки). |
| `regMxp` | Рега MXP | Не используется (MXP приостановлен). |

EwA2oGX: `regOgx ÷ projectRegs`, `regOgx ÷ showUp`, `aiesecOrgSignup ÷ projectRegs`,
`aiesecOrgSignup ÷ showUp`, `aiesecOrgSignup ÷ regOgx`. Все формулы описаны в
`src/lib/conversions/registry.ts` и считаются при чтении, поэтому смена формулы не требует
миграции данных.

Правила: нет данных или знаменатель 0 → «нет данных» (не 0); больше 100% показывается как есть
с пометкой «проверьте данные»; знаменатель меньше 20 → «малая база»; доля хранится как 0.10,
показывается как «10,0%» и дробь «60 / 600».

## Как подключить таблицу регистраций

### Один раз: ключ Google (сервисный аккаунт)
1. https://console.cloud.google.com → создайте проект (любое имя).
2. «APIs & Services» → «Library» → найдите **Google Sheets API** → Enable.
3. «APIs & Services» → «Credentials» → «Create credentials» → **Service account** → имя, например
   `ewa-reader` → Done.
4. Откройте созданный аккаунт → вкладка «Keys» → «Add key» → «Create new key» → **JSON** → файл скачается.
5. Vercel → проект → Settings → Environment Variables → добавьте `GOOGLE_SERVICE_ACCOUNT_JSON`,
   значение — **всё содержимое** скачанного файла. Отметьте Sensitive. Сделайте Redeploy.

Ключ хранится только на сервере; сайт читает таблицы, но не может их менять.

### Для каждого проекта
1. В Google-таблице регистраций: «Настройки доступа» → добавьте email сервисного аккаунта
   (виден в блоке «Настройки источников») как **читателя**.
2. На странице проекта → «Настройки источников» → вставьте ссылку → «Проверить доступ».
3. Выберите лист и колонку email (сайт предложит сам), по желанию — время, имя, телефон, UTM.
4. «Сохранить и прочитать». Потом обновляйте кнопкой «Обновить из источника» (не чаще раза в 30 с).

Без ключа Google можно загрузить файл: Google Таблицы → Файл → Скачать → CSV или .xlsx →
«Или загрузите файл таблицы». Файл не сохраняется.

Если таблица стала недоступна, сайт продолжает показывать последние прочитанные данные и
пишет, что обновление не удалось.

### oGX-кампания
«Настройки источников» → «oGX-кампания проекта» → выберите кампанию трекера. Заявки других
кампаний и заявки без UTM в «Рега oGX» не попадают.

## Как вводить числа
«Ввод данных» → Шоуап, AIESEC.org signup, дата «по состоянию на», примечание → «Сохранить».
Пока не сохранено, видно предпросмотр коэффициентов. Автозначения можно «Переопределить» —
только с причиной; «Вернуть авто-значение» отменяет. «Зафиксировать снимок» сохраняет текущие
числа в историю; снимки потом не меняются.

## Дубликаты и проверка на фейки
Одинаково для таблицы и для заявок oGX (`src/lib/conversions/quality.ts`):

- email: обрезка пробелов, нижний регистр; для gmail.com/googlemail.com убираются точки и `+tag`
  (настройка `gmailCanonical`). Пустые и некорректные email не считаются.
- одна запись на человека, остаётся самая ранняя; одинаковый телефон при разных email —
  флаг `possible_duplicate`, без склейки.
- флаги и веса по умолчанию (сумма ограничена 100):

| Флаг | Вес | Что значит |
|---|---|---|
| `invalid_email_format` | 80 | опечатка в домене (gmial.com…) или кривой адрес |
| `disposable_email` | 60 | одноразовая почта |
| `test_words` | 45 | test, тест, asdf, qwerty, «aaaa» в имени |
| `placeholder_phone` | 35 | 777 777 77 77, 1234567 и т.п. |
| `gibberish_name_or_email` | 30 | набор согласных без гласных |
| `no_mx` | 30 | домен не принимает почту (таймаут, кэш; при сбое DNS проверка пропускается) |
| `burst` | 25 | ≥ 5 записей в одну минуту с одного IP (без IP — с одного домена) |
| `possible_duplicate` | 10 | тот же телефон, другой email |
| `missing_utm` | 5 | пустая UTM-колонка (только если она выбрана) |

- статусы: **valid** < 30, **suspicious** 30–69, **quarantined** ≥ 70. Решения админа:
  **approved** / **rejected** — обратимы, записи не удаляются.
- в итог входят valid, approved и suspicious (с пометкой «на проверке»); карантин и фейки — нет.
  Переключатель «Учитывать в итоговом числе» исключает suspicious. Рядом всегда «строгое» число
  (только valid + approved) и разбивка «записей → −дублей → −карантин → итог».

Веса, пороги, `gmailCanonical`, `checkMx`, `mxTimeoutMs`, `burstMinRecords`, `burstWindowMin`
можно переопределить без деплоя записью `AppSetting` с ключом `conversions.quality`
(любое подмножество полей, см. `src/lib/conversions/settings.ts`).

Очередь проверки: «Качество данных» → «Очередь проверки» (`/projects/{slug}/review`).

## Приватность
- В новых таблицах нет имён, email и телефонов: строки таблицы регистраций хранятся как хэш
  нормализованного email, флаги, риск, маска (`a***@gmail.com`) и номер строки. Решения —
  по ключу (проект, источник, хэш).
- Заявки oGX и так лежат в БД; в очереди админ видит их email и имя.
- Логи не содержат тел запросов и персональных данных. Всё доступно только админу (страницы
  проектов закрыты логином); `publicView()` в `state.ts` отдаёт только агрегаты, если проекты
  когда-нибудь станут публичными.
- Все изменения пишутся в `ConversionAudit` (кто, когда, что).

## Модель данных (миграция `0006_conversions`)
`ProjectConversionConfig` (таблица, oGX-кампания, `countSuspicious`, ручные значения и
переопределения, состояние последнего чтения), `ConversionSnapshot` (история, только
добавление), `RowReview` (по человеку: статус, флаги, решение), `ConversionAudit`.

## Как позже включить EwA2MXP
1. `registry.ts`: `enabled: true` у типа `ewa2mxp`, у двух его коэффициентов и у входа `regMxp`.
2. Дать `regMxp` источник: например, MXP-кампанию в `ProjectConversionConfig` и подсчёт по её
   заявкам по образцу `evaluateOgx` в `state.ts` (или ручной ввод по образцу `showUp`).
3. Добавить поле в «Ввод данных» и строку в «Числа»; тесты из `tests/conversions` расширить.

`projectRegs = 600`, `showUp = 300`, `regOgx = 60`, `aiesecOrgSignup = 30` → 10,0% · 20,0% ·
5,0% · 10,0% · 50,0% (см. `tests/conversions/compute.test.ts`).
