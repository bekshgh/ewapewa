# Заявки Business Cup → трекер AIESEC: памятка для разработчиков Zimran

**Зачем.** Сейчас трекер AIESEC узнаёт о заявке только из скрипта `/t.js` в браузере участника. Блокировщик рекламы, закрытая вкладка или медленная отправка — и заявки на сайте нет, поэтому цифры не сходятся с вашей выгрузкой. Если ваш сервер сам будет отправлять каждую заявку нам, мы увидим все заявки и с теми же метками, что у вас.

Скрипт `/t.js` на странице формы оставьте: он записывает переходы и аналитику формы, а повторы склеиваются автоматически.

## 1. Куда и когда отправлять

После того как заявка **успешно сохранена** у вас, отправьте `POST`:

```
POST https://aieseckz.vercel.app/api/webhooks/tilda-lead
Content-Type: application/json
X-Webhook-Secret: <секретный ключ — передадим отдельно, не в общем чате>
```

- Одна заявка — один запрос. Если участник отправил форму повторно, повторная отправка — отдельный запрос.
- Отправлять лучше в фоне (очередь или отдельная задача), чтобы ответ участнику не ждал нашего сервера.
- При ошибке сети или ответе `5xx` повторите запрос через 1, 5 и 30 минут. Повторная отправка той же заявки безопасна: мы её склеим и дубля не будет.

## 2. Что передавать

```json
{
  "email": "student@example.com",
  "phone": "+77011234567",
  "name": "Имя Фамилия",
  "submittedAt": "2026-11-03T14:16:00+05:00",
  "pageUrl": "https://businesscup.zimran.io/en/apply?utm_source=instagram&utm_medium=bio",
  "formname": "businesscup-apply",

  "click_id": "k3j9x2…",
  "utm_source": "instagram",
  "utm_medium": "bio",
  "utm_campaign": "businesscup_f26",
  "utm_content": "tapter",
  "utm_term": "",

  "Participation type": "Already have a team",
  "Position in team": "Captain",
  "Team name": "…",
  "University": "…",
  "Year of study": "3",
  "Major": "…",
  "Interested in a career at Zimran": "…",
  "Previous AIESEC project": "…"
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `email` и/или `phone` | да | Хотя бы одно. По ним мы сопоставляем заявку с другими записями. |
| `pageUrl` | да | Полный адрес страницы, на которой стоит форма, с параметрами. По нему заявка без меток попадает в проект Business Cup. |
| `submittedAt` | желательно | Время заявки в ISO 8601 с часовым поясом. Если нет — время получения. |
| `click_id` | очень желательно | Идентификатор перехода по ссылке AIESEC (см. ниже). Даёт точную привязку к ссылке. |
| `utm_*` | желательно | Метки, с которыми пришёл участник. |
| `name`, `formname` | нет | Имя участника и название формы. |
| Ответы формы | желательно | Любые поля анкеты под их обычными названиями (как в выгрузке). Они нужны для прогноза явки. |

Лишние поля можно присылать: мы сохраняем тело запроса целиком.

## 3. Откуда взять `click_id` и метки

Участник приходит по ссылке AIESEC (`aieseckz.vercel.app/r/…`). Она перенаправляет на вашу страницу с параметрами `click_id` и `utm_*` в адресе. Скрипт `/t.js` на вашей странице сохраняет их в cookie на **вашем** домене на 30 дней:

```
tl_click_id, tl_utm_source, tl_utm_medium, tl_utm_campaign, tl_utm_content, tl_utm_term
```

Самый простой способ — при отправке формы прочитать их на фронтенде и передать вместе с заявкой на ваш бэкенд:

```js
function trackingTags() {
  const read = (name) => {
    const m = document.cookie.match(new RegExp("(?:^|; )tl_" + name + "=([^;]*)"));
    return m ? decodeURIComponent(m[1]) : "";
  };
  const url = new URLSearchParams(location.search);
  const out = {};
  for (const k of ["click_id", "utm_source", "utm_medium", "utm_campaign", "utm_content", "utm_term"]) {
    const v = url.get(k) || read(k);
    if (v) out[k] = v;
  }
  out.pageUrl = location.href;
  return out;
}
// при отправке формы: { ...answers, ...trackingTags() }
```

**Тот же источник стоит использовать и для вашей колонки «Метка».** Сейчас у трети заявок она пустая. Отчасти потому, что метки, похоже, берутся только из адреса текущей страницы и теряются при переходе с лендинга на форму. Cookie `tl_*` переживают переходы и живут 30 дней.

## 4. Ответы

| Код | Тело | Что значит |
|---|---|---|
| `200` | `{ "ok": true, "leadId": "…", "deduped": false }` | Заявка записана. `deduped: true` — склеена с уже существующей записью. |
| `401` | `{ "ok": false, "error": "Unauthorized" }` | Нет секретного ключа или он неверный. Повторять бесполезно. |
| `422` | `{ "ok": false, "error": "Invalid payload" }` | Тело не JSON-объект. |
| `5xx` | — | Наша ошибка: повторите позже. |

## 5. Как проверить

1. Тестовый запрос (проверяет только ключ):
   ```bash
   curl -X POST https://aieseckz.vercel.app/api/webhooks/tilda-lead \
     -H "Content-Type: application/json" -H "X-Webhook-Secret: <ключ>" \
     -d '{"test":"test"}'
   ```
   Ожидаемый ответ: `{"ok":true,"message":"Test ping received"}`.
2. Отправьте тестовую заявку с почтой вида `test+zimran@…`. Попросите нас проверить, что она появилась на странице Leads и в разделе Webhook. Потом мы её удалим.
3. Через пару дней сверим вашу выгрузку с сайтом на странице «Сверка регистраций». Расхождений быть не должно.

## 6. Ещё две просьбы

- **Ссылка «Пригласить команду»** на экране «Спасибо» и в письме после регистрации. Например: `https://businesscup.zimran.io/en/apply?utm_source=referral&utm_medium=team&utm_content=team_invite`. Сейчас сокомандники приходят по голой ссылке от капитана: у 43% из них метки нет.
- **Вопрос «Откуда вы узнали о Business Cup?»** со списком вариантов. Пусть будет запасным ответом для тех, кто пришёл без метки.

## Личные данные

Отправка только по HTTPS. Ключ хранить в переменных окружения сервера, не во фронтенде и не в репозитории. Контакты на стороне AIESEC видят только одобренные члены команды трекера.
